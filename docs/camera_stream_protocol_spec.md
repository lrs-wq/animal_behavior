# 喂食器与喂水器场景摄像头参数及流协议要求

版本：1.0  
日期：2026-07-30

## 1. 摄像头参数配置

| 参数 | 要求 |
| --- | --- |
| AI算力 | 不低于 0.25 TOPS，必须明确为 INT8 算力 |
| DDR | 不低于 128 MByte，即 1 Gbit；128 Mbit 只有 16 MB，不满足要求 |
| CPU | 双核 ARM，不低于 1.0 GHz |
| 图像传感器 | 不低于 2 MP 低照度 CMOS，推荐 1/2.8 英寸 |
| 镜头 | 固定焦 2.8 mm，水平视场角推荐 80°～100° |
| 主码流 | 推荐 1920×1080、20 FPS；最低 1280×720、15 FPS |
| 编码器 | 独立硬件 H.264 编码器 |
| 夜视 | 850 nm 红外、机械 IR-CUT、智能防过曝 |
| 宽动态 | 推荐真 WDR 不低于 100 dB |
| 图像处理 | 支持 AE、AWB、3D 降噪、背光补偿和 50 Hz 防频闪 |
| 网络 | 百兆网口或稳定 Wi-Fi，推荐同时支持 2.4 GHz 和 5 GHz |
| 校时 | 支持 NTP，时间误差不超过 1 秒 |
| 可靠性 | 支持硬件看门狗、断网恢复、远程 OTA 和固件回滚 |
| 音频 | 默认关闭 |
| OSD | 关闭时间水印、厂商检测框和其他叠加内容 |

`0.25 TOPS + 128 MB DDR`用于 ISP、硬件编码、网络推流以及可选的轻量触发功能，不用于运行项目完整模型。

## 2. 推荐主码流配置

```yaml
video:
  codec: H.264
  profile: Main
  level: "4.0"
  pixel_format: yuv420p
  resolution: 1920x1080
  fps: 20
  rate_control: CBR
  bitrate_kbps: 3072
  gop_frames: 20
  idr_interval_seconds: 1
  b_frames: 0
  audio: false
  osd: false
```

允许范围：

- 1080p、20/25 FPS：2.5～4 Mbps；
- 720p、15/20 FPS：1.2～2 Mbps；
- GOP 推荐 1 秒，最长不得超过 2 秒；
- 帧时间戳必须单调递增；
- 必须支持标准 H.264，不能只提供 H.265；
- RTSP 和 RTMP 应复用同一路 H.264 编码结果，不得分别重复编码；
- SPS/PPS 应在建流时提供，并推荐在 IDR 关键帧处周期性重复；
- 不使用厂商私有智能编码、私有封装或不可关闭的动态降帧功能。

## 3. 画面与安装要求

- 喂食器或喂水器主要区域必须完整、清晰可见；
- 画面应覆盖设备前方约 0.5～1 米的猫咪接近区域；
- 保留一定家具和猫咪用品背景，不能只拍摄设备本体；
- 摄像头安装后画面方向必须正确，不能只依赖播放器旋转元数据；
- 避免饮水器、透明储水罐、金属碗或墙面造成严重红外反光；
- 夜间降噪不能抹除猫咪轮廓、毛发纹理和姿态关键部位；
- 猫咪位于设备区域时，应保证目标尺寸足够，不得长期只占画面极小区域。

## 4. RTSP协议要求

| 参数 | 要求 |
| --- | --- |
| 协议版本 | RTSP 1.0 |
| 工作模式 | 摄像头提供稳定 URL，服务器主动拉流 |
| 视频承载 | H.264 over RTP/RTCP |
| RTP时钟 | H264/90000 |
| 传输模式 | 必须支持 RTP over RTSP/TCP interleaved |
| UDP | 可选，仅用于稳定的局域网环境 |
| 连接方式 | 单播，不能只支持组播 |
| 默认端口 | 554，允许配置 |
| 鉴权 | Digest 优先，每台设备使用独立账号和密码 |
| 保活 | 支持 OPTIONS 或 GET_PARAMETER |
| 并发拉流 | 至少支持 2 个客户端同时拉流 |
| 首帧时间 | 推荐不超过 2 秒，最长不超过 5 秒 |
| 会话恢复 | 客户端断开后可重新建立会话，不需要重启摄像头 |

RTSP 地址示例：

```text
rtsp://user:password@192.168.1.100:554/live/main
```

RTSP/TCP interleaved允许RTP/RTCP数据与RTSP控制连接复用；H.264的RTP封装应符合：

- [RFC 2326：Real Time Streaming Protocol](https://www.rfc-editor.org/rfc/rfc2326)
- [RFC 6184：RTP Payload Format for H.264 Video](https://www.rfc-editor.org/rfc/rfc6184)

局域网优先使用 RTSP/TCP。公网或跨家庭网络不得直接暴露 554 端口，应通过 VPN、家庭网关或流媒体中继访问。

## 5. RTMP协议要求

| 参数 | 要求 |
| --- | --- |
| 协议版本 | RTMP 1.0 over TCP |
| 工作模式 | 摄像头主动向流媒体服务器推流 |
| 默认端口 | 普通 RTMP 使用 1935；安全公网接入推荐 RTMPS/443 |
| 封装 | FLV |
| 视频编码 | H.264/AVC |
| 音频 | 不需要，默认关闭 |
| 关键帧 | 推荐每 1 秒一次，最长不得超过 2 秒 |
| AVC头 | 建立连接时必须发送 AVC sequence header |
| 时间戳 | 必须单调递增，重连后正确开始新会话 |
| 断线重推 | 支持自动重连，建议按 1、2、5、10、30 秒退避 |
| 鉴权 | 每台摄像头使用独立 stream key 或短期 token |
| 远程配置 | 支持远程更新服务器地址、应用名和 stream key |

RTMP 推流地址示例：

```text
rtmp://media.example.com:1935/live/{camera_stream_key}
```

推荐链路：

```text
摄像头
  -> RTMP或RTMPS推流
  -> 流媒体服务器
  -> 生成RTMP或RTSP播放地址
  -> 推理服务器拉取播放流
```

RTMP 摄像头通常是主动推流设备，必须先接入 MediaMTX、SRS、Nginx-RTMP 或同类流媒体服务。传统 RTMP/FLV 主码流必须使用 H.264，不接受仅支持私有 H.265 增强 RTMP 的设备。

## 6. 网络要求

以 1080p、3 Mbps 主码流计算：

- 单协议持续上行带宽至少为视频码率的 1.5 倍；
- 3 Mbps 码流至少需要稳定 4.5 Mbps 上行带宽；
- 推荐每台摄像头可用上行带宽不低于 8 Mbps；
- RTSP 远程拉流和 RTMP 同时工作时，推荐可用上行带宽不低于 10 Mbps；
- Wi-Fi RSSI 推荐不低于 -65 dBm；
- 持续丢包率推荐低于 0.5%，不得长期超过 1%；
- 摄像头必须支持 NTP，设备时间误差不超过 1 秒。

## 7. 不可接受条件

以下任一条件出现时，设备不得通过选型：

- AI 算力低于 0.25 TOPS INT8；
- DDR 低于 128 MByte，或供应商将 128 Mbit 描述为 128 MByte；
- 主码流低于 720p 或低于 15 FPS；
- 只支持 H.265，不支持标准 H.264；
- 只支持厂商 App 或 P2P 云服务，不能提供原始 RTSP URL 或 RTMP 推流配置；
- RTSP 只支持 UDP 或组播，不支持 RTP over RTSP/TCP；
- RTMP 使用私有封装或私有 H.265 增强协议；
- GOP 超过 2 秒、帧率频繁漂移或时间戳回退；
- 画面带有不可关闭的检测框、水印或严重隐私信息；
- 夜间猫咪轮廓无法辨认，或设备区域出现严重红外过曝；
- 断网恢复后必须人工重启设备才能恢复推流；
- 在 128 MB DDR 条件下通过两次独立编码实现 RTSP 和 RTMP 双协议输出。

## 8. 设备验收测试

量产或批量采购前至少完成：

1. RTSP/TCP 连续拉流 72 小时；
2. RTMP 或 RTMPS 连续推流 72 小时；
3. 如果业务要求双协议同时开启，再进行 24 小时并发测试；
4. 检查设备无 OOM、死机、花屏、断流和持续内存增长；
5. 分别断网 30 秒、5 分钟和 30 分钟，恢复后应在 30 秒内自动重新建流；
6. 使用项目实际运行环境检查分辨率、帧率、码率、关键帧间隔和时间戳；
7. 使用白天、低照度和红外家庭场景确认猫咪、喂食器和喂水器均清晰可辨；
8. 检查黑猫、快速经过、反光水碗、透明水箱、移动窗帘和毛绒玩具等困难场景。
