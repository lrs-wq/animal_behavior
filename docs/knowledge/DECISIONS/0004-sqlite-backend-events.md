# 0004：SQLite 视频源归属与独立后端事件发送

- 状态：accepted
- 日期：2026-09-05
- 契约更新：2026-09-07，按用户确认的驼峰 JSON 字段发送
- 范围：用户视频源登记、直播事件记录和后端接口

## 决策

1. SQLite 保存真实用户、RTMP 与事件文件映射、登记版本、读取游标、不可变待发请求及结果。数据位于 /data/Eating_behavior/events；源码与服务模板位于 /root/Eating_behavior，凭据由 /etc 受控环境文件提供。
2. 直播入口读取数据库登记，并报告生产者源与版本。发送器导入前检查归属证据，未登记源不自动发送；实际客户关系不进入源码或知识库。
3. 保留现有 JSONL 作为推理与发送进程之间的边界。生产者完成 flush/fsync 后，发送器按完整行消费，以事务同时提交游标与 outbox，不在推理循环内调用远程接口。
4. 对外仅发送 eventId、userId、eventType，Content-Type 保持 application/json；内部队列保留 event_id/user_id/event_type，HTTP 发送时转换字段，record_id 直接用作幂等键。仅转换出现事件与姿态事件，完整进食区间和余粮占位不发送。
5. 首次及变更登记从文件末尾接入，避免历史数据或前一归属被自动上报。相同登记无副作用；变更取消旧待发并要求重启生产者，有效在途租约会阻止变更。
6. 网络和服务端临时错误退避重试；鉴权和契约错误持久暂停，修复后显式恢复。成功同时校验 HTTP 状态、success 和 eventId；HTTP 200/201 包装的业务 code 先按错误分类处理，业务成功仍须有匹配 ID 的成功回执；不跟随重定向，不向日志输出原始响应、凭据或流地址。
7. 固定端点、单发送进程锁、带令牌的过期租约、源内发送顺序和有界活跃队列用于恢复与隔离。文件替换/截断或生产者归属不一致时保留游标并停止导入。

## 取舍与后续边界

独立发送进程无需 GPU 或第三方网络库，后端延迟不会阻塞推理。JSONL 是既有边界，改动范围小；
该方案仍不是行为状态机与 outbox 的原子提交，不能覆盖持久记录之前的进程崩溃或不同 ID 的语义重复。
后端必须按 event_id 幂等。历史回放、归档保留期限、容量监控和状态机检查点需独立设计。

## 验证证据

- tests/test_alerts.py：事件映射、归属、事务回滚、文件异常、积压限制、租约恢复、幂等、HTTP 错误与响应丢失。
- tests/test_live_inference_interval.py：登记视频源启动与输出目录一致性。
- docs/backend_event_delivery.md：初始化、真实用户登记、服务配置和恢复操作。
- src/eating_behavior/events.py：JSONL 持久写入。
- deploy/systemd/eating-behavior-events.service：独立常驻发送服务与目录隔离。

## 后续用户字段修订

2026-09-07 起，后端 userId 为 JSON 整数，用户名独立保存；旧库及已明确拒绝的待发记录按 ADR 0005 显式迁移。日常重试仍保持固定用户归属和事件 ID。
