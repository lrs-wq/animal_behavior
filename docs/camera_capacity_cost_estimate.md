# 10 万路摄像头 0.5FPS 全量检测容量与费用保守测算

## 前置说明

本文档只是规划阶段的保守估算，不能替代真实压测。正式采购云资源或自建机房前，必须先完成两类验证：

1. 压测当前模型链路，包括图片接入、解码、检测、花色分类、身份匹配、事件写入、审核队列和数据库写入。
2. 评估摄像头侧宠物检测效果，包括误检率、漏检率、触发频率、截图质量、是否能返回宠物框、弱光和遮挡场景表现。

本版按每路摄像头 0.5FPS 候选图片估算，并假设每张候选图片都需要进入服务端检测。最终成本仍然高度依赖摄像头侧粗检质量；如果实际触发频率高于 0.5FPS，或者误检很多，实际 GPU、审核和存储成本都会上升。

补充说明：

- 云服务器适合前期压测、快速扩容、业务模型未稳定阶段。
- 自建机房适合长期稳定负载，并且团队具备 GPU 服务器、网络、监控、故障处理和备件管理能力。

- 不建议保存全部候选图片。10 万路摄像头如果按 0.5fps 上传并长期保存，存储和带宽仍然很大，应只保存事件图、抽样图、裁剪图和短期排查数据。

保守建议：

- 0-1 万路摄像头：优先云服务器，先完成业务和模型闭环。
- 1-3 万路摄像头：云为主，自建小集群做压测和成本验证。
- 3-5 万路摄像头：开始认真评估自建，尤其是负载稳定、地域集中、带宽可控的场景。
- 5 万路以上摄像头：如果业务稳定增长，自建或混合云通常更经济。
- 10 万路摄像头：建议采用混合模式，云端承担弹性峰值、灰度发布和灾备，自建承担稳定基础流量。

## 表 3：高端 GPU 是否可能节省成本

高端 GPU 不一定必然省钱，关键看“单月价格 / 实测有效 FPS”是否低于 A10。以当前 A10 控制台价格 6093.81 元/月、保守吞吐 300 FPS 估算，A10 的云端 GPU 价格效率约为 20.3 元/月/FPS。高端 GPU 只有在单位 FPS 成本更低时才值得替换。

高端 GPU 选型建议：

- 优先压测 L20，因为阿里云官方规格中 `gn8is` 使用 L20 48GB，公开价格又没有比 A10 高太多，最可能降低单位推理成本。
- `gn8is` 可能只在部分地域开放，实际采购前需要在目标地域控制台确认库存、价格和是否需要联系销售。
- A100、H20、L40S 等更高端 GPU 可能减少机器数量、机柜数量和运维复杂度，但如果云端单价过高，未必比 L20/A10 便宜。
- 如果服务端图片检测模型较小，瓶颈可能在 CPU 解码、图片预处理、网络队列、Python 调度或后处理，而不是 GPU 算力。此时换更贵的 GPU 不一定能线性提升吞吐。
- 最终选择应以真实模型、真实图片、真实 batch size、TensorRT/FP16 优化后的压测结果为准。

规格和价格参考：

- A10 价格按当前控制台截图中的 `ecs.gn7i-c16g1.4xlarge` 6093.81 元/月估算。
- L20 规格参考阿里云官方 `gn8is` 说明，公开资料显示其使用 NVIDIA L20 48GB。
- L20 价格使用阿里云开发者社区公开参考价区间，最终价格必须以目标地域控制台下单页为准。

## 需要压测的关键指标

上线前至少压测以下指标：

| 指标 | 目标 |
|---|---:|
| 单 A10 节点 batch 推理吞吐 | >= 300 FPS |
| 单 A10 节点稳定摄像头数 | >= 350 路，按 0.5fps/路和冗余后口径 |
| 单 L20 节点 batch 推理吞吐 | >= 600 FPS，达到该值后才有明确成本优势 |
| P95 端到端延迟 | <= 3-5 秒 |
| 摄像头侧宠物粗检误检率 | 越低越好，需按真实场景统计 |
| 摄像头侧宠物粗检漏检率 | 必须低于业务可接受阈值 |
| 服务端二次过滤误报事件 | <= 业务审核可承受范围 |
| 单机 GPU 利用率 | 60%-80%，避免长期满载 |
| 单机 CPU 利用率 | <= 70%，避免解码、图片处理和队列拥塞 |
| 队列积压时间 | 高峰期可恢复，不持续增长 |

如果压测结果达不到 `300 FPS/节点`，则需要按实测吞吐重新计算。例如实测只有 150 FPS/节点，则 10 万路摄像头所需 GPU 节点数量需要接近翻倍。
